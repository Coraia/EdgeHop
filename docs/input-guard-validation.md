# 锁屏输入保护：行为与实机验收

对应 GitHub Issue #2。用户确认的行为：锁屏时退回 Mac 并暂停跨屏，解锁后恢复可切换，不自动返回 Omarchy。

## 修改前列出的失败路径

- 锁屏后仍进入 remote，鼠标可转发但键盘被系统安全输入截留。
- 已经 remote 时锁屏，安全输入截断 key-up，导致 Omarchy 修饰键/鼠标按钮残留。
- 锁屏界面强制显示光标，覆盖进入 remote 时的一次性隐藏。
- 锁屏之前的边缘停留、待切换快捷键在解锁后继续触发，造成意外切换。
- 安全输入关闭后仍保持暂停，或关闭时自动返回远程，导致输入归属不明确。
- 不在当前控制台会话/会话状态读取失败，却仍允许远程输入。
- 锁屏期间客户端重连，重新同步错误的 remote 状态。
- 状态检查与事件回调并发，转发或消费了应留在本地的事件。
- 在 HID 回调中查询 WindowServer，或持有事件回调需要的锁时查询，形成等待环并引发严重输入延迟；查询必须在后台且不持有输入状态锁。
- 暂停时网络发送失败/队列积压，客户端仍注入排队输入；需保留已有断线释放机制并发送有序返回消息。
- 把真实设备日志或人工观察误当作自动 E2E，通过检查不能证明未测场景。

## 验收步骤（两台真实设备）

1. 构建候选应用，保存已安装版本的备份及两者哈希；使用同一应用路径运行候选。
2. 启动 `scripts/observe-input-guard.py`，将证据保存到仓库外。脚本只采集锁屏/安全输入、光标元数据和两端控制模式日志，不采集键盘内容、密码或剪贴板。
3. Mac 解锁：将鼠标切到 Omarchy，按 Super+Esc，观察只有 Omarchy 系统菜单打开。
4. 已处于 Omarchy 时锁屏：确认退回 Mac，客户端记录 returned to Mac；持续推共享边缘和按切换快捷键不得重新进入 remote。
5. 锁屏界面按 Esc，再移动鼠标：确认仍保持本地状态。
6. 解锁：确认暂停原因消失，未自动返回 remote。移开共享边缘后重新跨屏，应恢复远程；Super+Esc 仍只作用于 Omarchy。
7. 如需补充：安全输入开启/关闭、按键或按钮保持时锁屏、锁屏期间客户端重连、启动时已锁屏、会话不可用。未完成的场景必须标注未验证。
8. 结束时保留观察 JSONL、过滤后的两端日志、操作观察、命令返回码、构建信息和 SHA256SUMS。最后才执行适用的完整验收；不在开发中反复执行完整 E2E。

实现采用独立后台查询，名义轮询间隔 100 ms；不承诺零延迟检测。输入回调及切换路径只读已检测状态，检测到限制后将暂停与返回本地的处理串行化。

## 系统边界

[Apple TN2150](https://developer.apple.com/library/archive/technotes/tn2150/_index.html) 说明安全输入会阻止 event tap 接收键盘事件。此修复采用控制权降级，不承诺在 Mac 锁屏时继续完整控制 Omarchy，也不禁用系统安全输入。
